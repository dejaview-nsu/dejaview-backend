# Развёртывание: чек-лист

Что проверить перед запуском backend на стенде или в продакшене. Переменные подробно - в README,
раздел «Конфигурация».

## Переменные окружения

- [ ] `POSTGRES_URL` - БД, к которой уже применены миграции (`db-migrate` из `dejaview-infra`).
- [ ] `APP_URL=https://<домен>` - из него собираются ссылки в письмах и адрес страницы `/auth/oidc`.
- [ ] `API_URL` - не задавать, если API на том же домене (по умолчанию `APP_URL`).
- [ ] `SMTP_URL=smtps://<сервер>:465`, `SMTP_FROM=noreply@<домен>`, `SMTP_USER`,
      `SMTP_PASSWORD` - см. [email.md](email.md), раздел «Продакшен».
- [ ] `SMARTCAPTCHA_SERVER_KEY` - **обязателен**: без него CAPTCHA при входе выключена (в логе при
      старте `WARN ... CAPTCHA при входе отключена`).
- [ ] `OIDC_YANDEX_*`, `OIDC_GOOGLE_*`, `OIDC_VK_CLIENT_ID` - для каждого включённого провайдера.
- [ ] Секреты - только в секретах сервера: не в git, не в образе, не во frontend.

`dejaview-infra/compose.yaml` пока не передаёт backend `APP_URL`, `SMTP_URL` и `SMTP_FROM`: без них
backend не стартует. `MINIO_*` и `INFERENCE_URL` оттуда backend пока не читает.

## nginx и домен

- [ ] Только HTTPS: у cookie `dv_session` и `dv_oidc` флаг `Secure`, VK не принимает `http`.
- [ ] `/api/v1/` проксируется в backend **без переписывания пути**: маршруты backend и `Path`
      cookie - с `/api/v1`. Остальное - frontend (SPA с маршрутами `/confirm-email` и `/auth/oidc`).
- [ ] `proxy_set_header X-Real-IP $remote_addr;` - заголовок перезаписывается, а не дополняется:
      по нему backend пишет IP в журнал безопасности и передаёт SmartCaptcha.
- [ ] Лимит 100 запросов в минуту на пользователя, ответ 429 (#17094 п. 3.4) - по контракту
      делает nginx.

## Провайдеры и внешние сервисы

- [ ] Боевые адреса возврата: `https://<домен>/api/v1/auth/oidc/{yandex,google,vk}/callback` - в
      приложениях провайдеров, см. [oidc.md](oidc.md).
- [ ] Google: приложение опубликовано («Publish app»), иначе войдут только Test users.
- [ ] VK ID: базовый домен - боевой, приложение доступно всем пользователям.
- [ ] SmartCaptcha: боевой домен в настройках капчи, ключ клиента - в сборке frontend, ключ
      сервера - в backend.
- [ ] Почта: SPF, DKIM и DMARC для домена отправителя.
- [ ] Исходящие соединения (если сервер их ограничивает): HTTPS до `oauth.yandex.ru`,
      `login.yandex.ru`, `oauth2.googleapis.com`, `openidconnect.googleapis.com`, `id.vk.com`,
      `smartcaptcha.yandexcloud.net`; SMTP-сервер, порт 465.

## После запуска

- [ ] `GET /health` → 200, `{"database":"ok"}`.
- [ ] В логе при старте `OIDC: подключены ...` - все нужные провайдеры, и нет предупреждения про
      CAPTCHA.
- [ ] Регистрация на свой адрес: письмо пришло не в спам, ссылка ведёт на боевой домен.
- [ ] Вход через каждого провайдера.

Несколько экземпляров backend безопасны: состояние (сессии, счётчики попыток, очередь писем)
хранится в PostgreSQL, письма разбираются через `SKIP LOCKED` без дублей, очистку каждый экземпляр
выполняет сам - повторное удаление ничего не ломает.

## Что смотреть в логе

| Строка | Что значит |
|---|---|
| `ERROR SmartCaptcha ответила 4xx - проверьте SMARTCAPTCHA_SERVER_KEY` | неверный ключ: CAPTCHA фактически выключена |
| `WARN письмо <N>: попытка <K> не удалась: ...` | SMTP недоступен или отклоняет письма |
| `WARN OIDC <провайдер>: ...` | вход через провайдера не удался, причина в строке |
| `ERROR фоновые задачи: ...` | фоновый поток не достучался до БД, повторит через 5 с |
