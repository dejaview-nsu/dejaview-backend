# Вход через Яндекс, Google и VK ID

Как зарегистрировать приложения у провайдеров и проверить вход. Устройство входа - раздел
«Решения» в [auth.md](auth.md).

## Общее

**Адрес возврата** (redirect URI) у всех провайдеров один по форме:

```
{API_URL}/api/v1/auth/oidc/<провайдер>/callback
```

Провайдер сверяет его символ в символ: схема, порт, путь, `/` в конце. Локально
`API_URL=http://localhost:8081`, в продакшене `API_URL` не задаётся - берётся `APP_URL`. Адресов
у приложения может быть несколько: локальный и боевой регистрируются рядом.

**Ключи** - в `.env` (локально) и в секретах сервера. ID клиента публичный, его видно в адресе
перехода к провайдеру. Секрет - как пароль. Приложения лучше заводить на командный аккаунт, а не
на личный.

**Страницы frontend.** После провайдера браузер попадает на `{APP_URL}/auth/oidc?provider=...&result=...`
(`success`, `registration_required`, `link_required`, `account_blocked`, `error`) - эту страницу и
`/confirm-email` делает frontend. Пока её нет, исход видно по `result` в адресе.

**Почему вход не удался** - знает только лог backend: пользователь видит одно сообщение «Не
удалось выполнить вход через ...», в логе - строка `OIDC <провайдер>: <причина>` или ответ
провайдера.

## Яндекс

1. oauth.yandex.ru → «Создать приложение» → **«Для авторизации пользователей»**.
2. Название `DejaView`, платформа **«Веб-сервисы»**, **Redirect URI** - адрес возврата с
   `/yandex/callback`. Suggest Hostname, если поле обязательно, - `http://localhost:8081`.
3. Доступы: «Доступ к адресу электронной почты» и «Доступ к логину, имени и фамилии, полу».
4. **ClientID** → `OIDC_YANDEX_CLIENT_ID`, **Client secret** → `OIDC_YANDEX_CLIENT_SECRET`.

Модерации нет, работает сразу с любым аккаунтом Яндекса.

## Google

1. console.cloud.google.com → новый проект `DejaView`.
2. **Google Auth Platform** («OAuth consent screen» в старом интерфейсе) → «Get started»: App name,
   User support email, Audience **External**, контактный email.
3. **Data Access** → scopes `openid`, `.../auth/userinfo.email`, `.../auth/userinfo.profile`. Это
   нечувствительные доступы: проверка приложения Google не нужна.
4. **Audience → Test users** - аккаунты, которыми будут входить. Пока приложение в статусе
   **Testing**, войти могут только они; для продакшена - «Publish app».
5. **Clients → Create client** → тип **Web application**, Authorized JavaScript origins - пусто,
   **Authorized redirect URIs** - адрес возврата с `/google/callback`.
6. **Client ID** (`...apps.googleusercontent.com`) → `OIDC_GOOGLE_CLIENT_ID`, **Client secret**
   (`GOCSPX-...`) → `OIDC_GOOGLE_CLIENT_SECRET`. Секрет показывается один раз.

Настройки иногда вступают в силу через несколько минут.

## VK ID

1. id.vk.com/about/business/go → кабинет VK ID → приложение, платформа **Web**.
2. **Базовый домен** и **доверенный Redirect URL** - адрес возврата с `/vk/callback`.
3. Доступ к **почте**.
4. **ID приложения** → `OIDC_VK_CLIENT_ID`. Защищённый и сервисный ключи не нужны: VK ID
   работает по OAuth 2.1, секрет приложения заменяет PKCE.
5. Новое приложение может быть доступно только владельцу - для продакшена включить для всех.

Ограничения VK:
- Redirect URL - **только `https`**, `localhost` не принимается. Домены бесплатных туннелей
  VK отвергает как вредоносные (`trycloudflare.com`). `*.lhr.life` (localhost.run) принимает, но
  этот туннель меняет адрес каждые несколько минут - для разовой проверки, не для работы.
  Надёжно - стенд с собственным доменом.
- У аккаунта VK может не быть email (только телефон) - вход через VK завершается ошибкой
  (`OIDC vk: провайдер не дал подтверждённый email` в логе).

### Проверка VK через туннель

Туннель должен вести туда, где на одном домене и страницы, и API: cookie `dv_oidc` ставится на
домене туннеля, и страница `/auth/oidc` должна её получить. То есть туннель - на frontend (или
другой прокси), который сам пересылает `/api/...` в backend, как nginx в продакшене.

```sh
ssh -R 80:localhost:<порт frontend> nokey@localhost.run   # выдаст https://<имя>.lhr.life
```

Backend запустить с `APP_URL` и `API_URL`, равными адресу туннеля, адрес возврата в кабинете VK
поменять на новый. Яндекс и Google на это время не работают: у них зарегистрирован локальный адрес.

## Частые ошибки

| Что видно | Причина |
|---|---|
| `redirect_uri_mismatch` у провайдера | адрес возврата отличается хоть на символ; не задан `API_URL` - тогда берётся `APP_URL` с портом frontend |
| Google: «Доступ заблокирован», `access_denied` | аккаунт не в Test users |
| в логе `invalid_client` / `client secret is invalid` | неверный ID или секрет, например приставка `GOCSPX-` вставлена дважды |
| в логе `нет cookie dv_oidc` | вход начат в одном браузере или профиле, закончен в другом (инкогнито); Safari не хранит `Secure` cookie с `http://localhost` - локально проверять в Chrome |
| в логе `не совпал state` | открыта старая вкладка или ссылка возврата из другого входа - начать заново |
| VK: «Обязателен протокол https» | VK не принимает `http`, нужен туннель или стенд |
| VK: «Ссылка ведёт на вредоносный сайт» | домен туннеля в чёрном списке VK |
