# Письма

Обработчики запросов не отправляют письма сами: они кладут строку в `email_outbox` тем же
SQL-запросом, что и свои данные. Фоновый поток (`src/background.cpp`) каждые 5 с берёт до 10
писем, отправляет по SMTP и удаляет отправленные. Сбой SMTP - повтор через 1, 2, 4 ... 60 минут,
после 8 неудач письмо помечается `failed` и через сутки удаляется. Подробнее - раздел «Решения»
в [auth.md](auth.md).

## Локально: Mailpit

Mailpit принимает любые письма и показывает их в браузере, никуда не пересылая.

```sh
docker compose up -d mailpit
```

В `.env` - `SMTP_URL=smtp://host.docker.internal:1025`, письма - на http://localhost:8025.
Вкладка **HTML Check** у письма показывает, какие приёмы вёрстки не поддерживают Gmail, Outlook и
другие клиенты.

## Настоящая отправка для проверки

Ящик на Яндексе:
1. Яндекс ID → Безопасность → **Пароли приложений** → пароль для «Почты». Обычный пароль для
   SMTP не подходит.
2. Почта → Настройки → Почтовые программы → разрешить доступ по IMAP/SMTP.
3. В `.env`:

   ```sh
   SMTP_URL=smtps://smtp.yandex.ru:465
   SMTP_FROM=<ящик>@yandex.ru
   SMTP_USER=<ящик>@yandex.ru
   SMTP_PASSWORD=<пароль приложения>
   ```

   `SMTP_FROM` должен совпадать с ящиком, иначе Яндекс ответит `553 Sender address rejected`.

Gmail - так же: `smtps://smtp.gmail.com:465`, пароль приложения (нужна двухфакторная
аутентификация).

Много тестовых адресов на одном ящике: `ящик+любое@gmail.com` приходит в `ящик@gmail.com`, а для
нас это другой email. Работает в Gmail, Яндексе и большинстве почтовых сервисов.

## Продакшен

- **Сервис отправки** - транзакционный (Yandex Cloud Postbox, Unisender Go и подобные) или почта
  для домена. Личный ящик не годится: лимиты и спам-фильтры.
- **Адрес отправителя на своём домене** (`noreply@<домен>`) и DNS-записи домена:
  - **SPF** - каким серверам разрешено слать почту от домена;
  - **DKIM** - подпись писем; открытый ключ в DNS выдаёт сервис отправки;
  - **DMARC** - что получателю делать с письмом, не прошедшим проверки.

  Без SPF или DKIM Gmail и Яндекс кладут письма в спам или отклоняют. Проверка: в Gmail
  «Показать оригинал» → `SPF`, `DKIM`, `DMARC` - `PASS`.
- **Только `smtps://`, порт 465.** С `smtp://` TLS включается, только если сервер его предложит:
  злоумышленник на пути может это предложение вырезать, и пароль уйдёт открытым текстом. Порт
  25 облака обычно закрывают.

### Короткие ссылки (временно, #18974)

Пока письма идут через личный ящик Яндекса, его антиспам отвергает письма на @gmail.com со
ссылкой на `dev.deja-view.ru` (`554 5.7.1 Message rejected under suspicion of SPAM`). Временный
обход на MVP - короткая ссылка clck.ru вместо полной:

```sh
EMAIL_LINK_SHORTENER=https://clck.ru/--
```

- Ссылку сокращает фоновая отправка перед каждой попыткой: `GET <EMAIL_LINK_SHORTENER>?url=<ссылка>`,
  в ответе короткая ссылка текстом. Сокращаются ссылки всех писем: подтверждение email, сброс и
  смена пароля.
- Не удалось сократить (нет соединения, 10 с без ответа, статус не 200, в ответе не ссылка,
  например капча) - письмо не уходит, попытка считается неудачной и повторяется по обычным
  правилам; в `last_error` - `сокращение ссылки: ...`. Полная ссылка при сбое не отправляется.
- Не задана или пустая - ссылки в письмах полные.

**Риск, принятый на время MVP.** Сокращатель отдаёт полную ссылку любому, кто знает короткий
код, а коды короткие и, похоже, выдаются по порядку: их можно перебирать. В ссылке
подтверждения - токен, по которому выдаётся сессия (живёт 24 ч), в ссылке сброса - токен смены
пароля (1 ч). Посторонний, нашедший ссылку раньше пользователя, входит в его аккаунт. Выключить,
как только письма пойдут через сервис отправки на своём домене (см. выше).

## HTML-шаблон

Шаблоны - `src/email/templates/<вид>.html`: `email_confirm.html`, `password_reset.html`,
`password_changed.html`. Их можно открыть в браузере. Подстановки `{{username}}` и `{{link}}`, значения экранируются для HTML. CMake
встраивает файлы в программу при сборке: после правки достаточно `cmake --build build`.

Правила вёрстки писем - в комментарии в начале `email_confirm.html`: таблицы вместо flex и grid,
стили только в `style="..."`, без скриптов, веб-шрифтов и внешних картинок, ширина 600px. Outlook
для Windows не понимает `border-radius` и `max-width` - там карточка будет с прямыми углами и во
всю ширину.

Текстовая версия письма (её показывают клиенты без HTML) - в `renderEmail`,
`src/email/message.cpp`: меняется вместе с шаблоном.

## Новый вид письма

Допустимые виды перечислены в `CHECK` колонки `email_outbox.kind`: вид, которого там нет,
добавляется миграцией. Чтобы добавить письмо:
1. Шаблон `src/email/templates/<вид>.html`.
2. В `CMakeLists.txt` - вид в списке `foreach(EMAIL_KIND ...)`, в `src/email/templates.cpp.in` и
   `templates.hpp` - константа `k<Вид>Html`.
3. В `renderEmail` - ветка для вида: тема, текст, HTML.
4. Обработчик кладёт письмо: `INSERT INTO email_outbox (user_id, kind, payload)`, в `payload` -
   ссылка и другие параметры шаблона.
5. Тест в `tests/email/message_test.cpp`.

## Если письмо не пришло

```sql
SELECT email_id, kind, status, attempts, last_error, next_attempt_at FROM email_outbox;
```

Отправленного письма в таблице нет: оно удаляется. `last_error` - ошибка libcurl и, если сервер
отказал, его ответ (адрес получателя в нём скрыт), в логе backend - строки
`письмо <номер>: попытка <N> не удалась: ...`. Отказ `5xx` с упоминанием спама - сервер отправки
отверг текст письма: его антиспам проверяет и ссылки в письме, см. «Продакшен». Пришло, но в
спам - проверить SPF и DKIM. `сокращение ссылки: ...` - не ответил сокращатель
(`EMAIL_LINK_SHORTENER`), письмо не отправлялось, см. «Короткие ссылки».
